# DEDL detailed operating reference

Version 1.0 — effective 26 October 2026. `docs/DEDL_RUNBOOK.md` is the daily entry point. Read the applicable sections here for weekly UBER, source onboarding, publication/recovery or a changed requirement; do not reload this entire reference without a reason. The scheduler is a bootstrap, not another rule copy. New user instructions supersede these rules.

## 1. Mandate and boundaries

Effective 27 October 2026: keep the existing daily **08:00 Asia/Singapore DEDL** full edition; the user's repair request additionally authorizes Market Watch open/close windows under `docs/LIGHTHOUSE.md`. Only the prohibition on session jobs is superseded. No separate NVIDIA, UBER, conflict, model-training, hourly research or checklist timers. The daily edition audits session gaps and deployment. Push-triggered build/deploy/delivery checks and manual recovery are not additional research schedules. A schedule is a target, not a guaranteed start or delivery time. Label delayed work and actual cutoffs honestly.

Keep the established website, daily edition and Telegram format. Keep the public output extensive: simplification removes duplicated research and instructions, not evidence, coverage, explanations or the weekly debate. Do not redesign navigation or delete archive pages in an operational cleanup. Retain all original editions and labelled corrections.

Use only lawfully accessible **zero-cost public/open-source information**. Publicly readable does not mean open-licensed or free to redistribute. No purchases, paid APIs, trials requiring payment, new subscriptions, account creation, paywall/authentication workarounds or undocumented/private API scraping. Use existing approved free access only when its rights cover the intended use. If blocked, record the gap and use an accessible original source; never invent an observation or imply the source was read in full.

This repository is public. Never commit private methodology, formulas, scores, thresholds, portfolios, trades, balances, account details, personal identifiers, chat IDs, credentials, unpublished working debates or confidential research. Public-safe observations and operational instructions may be stored here. The private algorithm needs a separately approved private home; do not install, train or deploy it through this runbook. No automatic trades.

## 2. Start each run from GitHub, not chat recollection

1. Resolve the current default-branch SHA. Read this runbook and `docs/DEDL_STATE.md`. Inspect `issues.json` for the latest edition, and use that edition as the layout/section reference. Read `docs/EDITORIAL.md` and `docs/LIGHTHOUSE.md` when relevant or changed. Read only relevant templates, source registers and recent reports; do not reload the entire archive.
2. Run `node scripts/run-context.mjs` when a checkout is available. It reports a bounded index of freshness, review gaps and reusable source metadata; it does not fetch news or certify evidence. Read the referenced original report before relying on a cached claim.
3. Check whether today's Singapore edition already exists. Resume unfinished publication or add a labelled correction rather than creating a duplicate issue. Preserve actual first-publication time. A missing edition requires a factual owner-facing explanation and, when delivery was missed, a public apology without an invented cause.
4. Plan one shared evidence-gathering pass across the desks. Reuse source records only after checking whether the underlying information changed. Never change an access timestamp without actually rechecking. Cache metadata and short public-safe observations, not restricted full-text articles or private raw feeds.

## 3. Research once, explain thoroughly

Cover Global, US, Europe, Asia and a daily Singapore focal lens. Maintain the five independent market coverage groups: US, Singapore, global ex-US/ex-Singapore, direct listed REITs/property trusts, and funds/ETFs. Keep editorial desks (Markets, Military, Parliament, Conflict, Cybersecurity) distinct from those market groups.

Daily scan: prices and completed sessions; rates, FX and commodities; material issuer filings/earnings; policy and public political statements; military/conflict and infrastructure; cybersecurity; logistics; AI/agentic systems; Singapore news; and promotions/card-term freshness. Scan all 11 market-sector groups where evidence permits. Current sector data cannot be inferred from one stock or a country index. Retain explicit gaps rather than replacing them with generic sector commentary.

Each material item needs: what happened; original source and observation period; evidence-supported cause versus inference; transmission to affected industries/markets; direct versus conditional effects; strongest plausible alternative or counterargument; what would confirm or invalidate the interpretation; and the next dated watchpoint. State unknowns. Distinguish price observations, estimates, forecasts, actor claims and DEDL interpretation.

Use exact timestamps and time zones when available; distinguish cash close, intraday, futures and after-hours. An official statement proves that the actor said something, not necessarily that the assertion is true. Public political posts require direct links, identity/office, platform and timestamp; separate rhetoric/proposals from enacted policy. Do not infer public opinion from a few posts or market causation from coincident price changes.

## 4. Desk work within the same slot

- **Markets / Lighthouse:** preserve daily context plus the restored session windows in `docs/LIGHTHOUSE.md`. Retain session dates, official calendars and all 11 sector categories. Audit overdue targets and actual live deployment. Preserve archives and identify real delays/evidence periods; never fabricate a historical cutoff.
- **Military:** strategic, public-safe context; Monday/Wednesday/Friday review target. No tactical tracking, sensitive coordinates, targeting assistance or operational details.
- **Parliament:** Tuesday/Thursday review target; optional Saturday item when substantive. Prefer official records; do not fill a quota.
- **Conflict:** only material verified changes; maximum five structured reports per Monday–Sunday Singapore week. Zero is valid. Corrections do not create another event. Do not bypass the cap by splitting one development into multiple IDs.
- **Cybersecurity:** daily global scan; publish material verified incidents, exploited vulnerabilities, regulatory developments and industry/supply-chain effects. Prefer CERT/regulator/operator notices. Label unverified attribution and claimed impacts. No exploit instructions, credentials or sensitive indicators.
- **Singapore:** daily review of regional military, cyber frontier, agentic agents, Parliament and markets. Explain local transmission, freshness and missing coverage. Promotions & Cards remains integrated: verify official terms, exclusions, eligibility, expiry and review dates. Overdue is not expired; stale records remain labelled/excluded by existing filters. No invented offers or age-only suitability claims.
- **Sunday:** sourced global economic-event outlook for the coming Monday–Friday, including policy, industry, AI, cyber, energy, transport/logistics, space and security where material. Verify schedules and time zones; show genuinely unverified days as gaps. Keep the five-day Telegram week-ahead layout.

## 5. NVIDIA, UBER and REDL — consolidated, not separate jobs

**NVIDIA daily change review:** examine direct disclosures and corroborating supplier evidence for AI demand/capital allocation and shifts toward HBM/memory, foundry/advanced packaging, server/rack manufacturing, networking, power/grid, cooling and generation. Distinguish commitments from shipments/revenue/cash. Include demand-quality, circular-financing, capex and execution risks. Reuse verified evidence across related sections. Publicly repeat unchanged background only if needed for comprehension; otherwise retain a compact no-change state.

**UBER:** daily material changes only. In the Saturday Singapore edition after the completed Friday US session, perform the complete weekly review. If missed, catch up in the next daily slot. Use a Singapore/completed-US-week key to prevent duplicates. Cover Gross Bookings, trips/MAPCs/frequency, operating profit and FCF per Gross Bookings, adjusted ecosystem cash flow when estimable, AV supplier diversity, utilization, unit economics, rent capture, capital intensity and distribution share where evidence exists. Examine earnings/filings, public insider disclosures, buybacks, AV partnerships, fleet/depot spending, regulation/litigation, insurance/labour/incentives, competition and bargaining power. A missing metric remains unavailable, not invented.

Preserve the **full sourced Bull Team / Bear Team debate** in the owner-facing output: quantify important claims, steelman both sides, challenge assumptions, retain contradictions and state each side's falsifiers. Do not choose a winner. Finish with a **Manager Decision Packet**: strongest arguments, unresolved questions, strengthening/weakening signals, changes since last week and next evidence. Publicly publish only a safe summary; never archive the private debate in this public repo or truncate the owner debate to fit Telegram.

**REDL daily disclosure check:** retain the studied investors—Brad Gerstner/Altimeter, Li Lu/Himalaya, Chris Hohn/TCI and Dev Kantesaria/Valley Forge. Explain why their public records are studied and what newly disclosed activity shows. Separate transaction date, filing date and holdings-as-of date. Delayed 13F snapshots cannot reveal daily buying. No new filing is not proof of no trading. Attribute inferred reasoning as inference, not the investor's stated intention. Study failures/exits and survivorship limitations, not only winners. Do not publish the private REDL mechanism.

**Company research:** keep the original DEDL result. An alternative business-model/valuation lens is an additional labelled review, never a way to relabel a failed or incomplete screen as passed. Use appropriate GAAP/non-GAAP reconciliation, currency, share-class/ADR ratios and corporate-action adjustments. Do not manufacture a common P/E or PEG where inappropriate. Company cards retain quality, valuation assumptions, price context when verified, expectations, bull/bear evidence, catalysts and invalidation. No model confidence percentages without validated prospective evidence.

## 7. Output and format contract

Keep the existing visual layout, issue numbering, archive paths, source register, corrections and liability notice. Preserve extensive full-issue explanations and tables; no arbitrary word/token limit may remove required debate, evidence or coverage. Use concise no-change text instead of repeated unchanged paragraphs. Keep public research separate from the owner's private decision system.

Telegram remains the existing HTML-formatted digest: **THE BIG PICTURE → WORLD WATCH → optional Sunday GLOBAL ECONOMIC EVENTS / WEEK AHEAD · MON–FRI → MARKET SNAPSHOT → Full issue link → notice**. A delivery apology remains a labelled prefix when needed. The existing formatter is authoritative: summary ≤330 characters, at most three headlines (title ≤130, date ≤30, context ≤180, HTTPS source ≤300), market note ≤350; total ≤4,096 characters. Sunday event updates: at most two, name ≤70/date ≤30/update ≤150/source ≤300. Week ahead: exactly five ordered dates, at most three items/day, each ≤140. Keep the same headings, spacing, escaping and disclaimer. Fit the digest by linking the extensive full issue—not by weakening the full issue.

## 8. Release and failure handling

1. Prepare one coherent public change against the current remote SHA: dated edition, homepage/index metadata and only necessary reviewed desk updates. Do not rewrite old editions or bump `delivery_revision` merely for documentation/maintenance.
2. Run `node --test`, Telegram `--dry-run`, `node scripts/run-context.mjs`, build, internal link check, editorial check, diff check and history check against the immutable base SHA. Tests validate contracts, not source truth; perform evidence/privacy/public-safety review separately.
3. Commit related changes atomically with an expected-head check. If the branch moved, reconcile before writing. Never force-push or overwrite another run's changes.
4. The main push pipeline validates/builds once, deploys Pages, then considers Telegram. The sender compares the prior issue/revision using the push's base SHA; unchanged delivery keys do not send. It verifies the deployed issue/revision marker before sending. Missing configuration is an explicit error, not silent success. Preserve the accepted message ID in the run record; acceptance is not subscriber receipt/read confirmation.
5. If Telegram acceptance is UNKNOWN after a network error, check the channel/receipt before manual recovery; do not blindly retry. Manual Telegram dispatch can duplicate a message and requires operator reconciliation. No additional scheduled retries. Report failed publication/delivery clearly to the owner; do not claim success from an index commit alone.
6. Update the compact public-safe `docs/DEDL_STATE.md` handoff when necessary: immutable observed head, latest issue, actual checks, material unresolved coverage/access gaps, next evidence and publication/delivery state. Link reports rather than copying them. Corrections remain append-only; normal handoff details may be compacted because Git preserves earlier versions. Never put private owner output here.

## 9. What this consolidation does not do

No deletion of historical research, new paid services, live trading, new research timers, visual redesign, relaxation of evidence standards, private algorithm changes or silent reduction of required output. PySR, tick, arch and MAPIE remain uninstalled research candidates, not proven production models. A smaller scheduler prompt saves repeated context; it does not erase ChatGPT account memory. Never claim memory was deleted without an actual supported memory operation.
