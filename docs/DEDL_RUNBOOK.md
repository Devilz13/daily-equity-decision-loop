# DEDL daily runbook

Version 1.0 — 26 October 2026. Authoritative daily entry point. Detailed/exception rules are in `docs/DEDL_REFERENCE.md`; read applicable sections, not the entire archive. Current user instructions supersede these files. Record changes here instead of appending conflicting scheduler prompts.

## One slot, free sources, private boundary

Use the existing **08:00 Asia/Singapore daily DEDL slot only**. No additional NVIDIA/UBER/conflict/model/session/checklist timers. Push validation/deployment and manual recovery are not research slots. Label delayed execution and actual evidence cutoffs. Do not claim continuous Linux uptime.

Use only permitted **zero-cost public/open-source information**. No purchases, paid APIs/trials, new subscriptions/accounts, paywall/authentication bypass or undocumented/private API scraping. Public visibility is not redistribution/AI permission. Missing access is an explicit gap. ACLED raw/API/AI use is rights-gated; World Monitor's hosted data API is not assumed free; Conflictly/Polyglobe have no verified free ingestion API here; BrotherEye's exact URL remains unconfirmed. Cite an aggregator only if used and retain original evidence. See reference §6 before onboarding/changing a source. No five-provider live feed is deployed.

This repository is public: **no private methodology**, formulas, scores, thresholds, portfolios, transactions, personal identifiers, chat IDs, credentials or unpublished owner debates. No trades. Store public-safe evidence metadata and handoffs only. Private modelling requires separately approved private storage/runtime; PySR/tick/arch/MAPIE remain research candidates, not installed production models.

## Each run

1. Resolve current default-branch SHA. Read this file and `docs/DEDL_STATE.md`; inspect `issues.json` and the latest edition for current state and exact format. Run `node scripts/run-context.mjs` if a checkout is available. It provides bounded metadata, not verified live data. Read only relevant changed reference sections, recent reports, source registers and templates. Never substitute stale chat recollection for current files.
2. If today's Singapore edition is already indexed, inspect publication/delivery and resume/correct it rather than duplicating it. Use actual first-publication and cutoff times. Explain missed publication/delivery factually; publish a labelled apology when appropriate, without inventing a cause.
3. Gather shared evidence once; reuse across sections after checking for changes. Never advance source access times without rechecking. Keep original URL/publisher, discovery source where relevant, event versus first-known/update times, source lineage, contradictions and last successful check. Ten copied reports are one chain. Separate claims, exercises, rhetoric, verified events and economic disruption; headline counts do not establish war probabilities or causation.
4. Cover Global/US/Europe/Asia with a daily Singapore focal lens. Retain independent US, Singapore, global ex-US/ex-Singapore, direct REIT and funds/ETF statuses. Editorial desks remain Markets, Military, Parliament and **Cybersecurity** plus Conflict. Review latest completed market sessions/pre-open context, all 11 sector groups where evidence permits, rates/FX/commodities, filings/earnings, policy, infrastructure/logistics and AI. No invented sector returns or retroactive opening reports.
5. Singapore: regional military, cyber frontier, agentic agents, Parliament and markets; verify official Promotions & Cards terms and review/expiry dates. Overdue is not expired. Cybersecurity receives a daily global scan; material verified industry/supply-chain effects only. Military review M/W/F, Parliament Tu/Th with optional substantive Saturday; no quota filler. Conflict only if material, maximum five structured reports per Singapore Monday–Sunday week. Strategic-only public military/conflict coverage; no tactical coordinates, targeting, exploit instructions or credentials.
6. Every material item explains what happened, dated evidence, evidenced cause versus inference, transmission, direct/conditional effects, strongest counterargument/alternative, confirmation/invalidation and next dated watchpoint. Separate cash close/intraday/futures/after-hours; GAAP/non-GAAP, currencies/ADRs and corporate actions. Political posts prove what an identified actor said, not that the claim is true, policy enacted or public opinion established. Missing verification remains DATA INCOMPLETE. An alternative stock lens never turns a failed/incomplete screen into a pass.

## NVIDIA, REDL, UBER and Sunday

- NVIDIA: daily material changes in direct demand/capital-allocation disclosures and corroborating HBM/memory, foundry/packaging, racks, networking, power/grid, cooling and generation evidence. Distinguish funding/commitments from deliveries/revenue/cash; include financing/overbuild/execution risks. Carry unchanged state compactly, without repeated filler.
- REDL: daily public-disclosure check for Gerstner/Altimeter, Li Lu/Himalaya, Hohn/TCI and Kantesaria/Valley Forge. Explain why studied, new disclosed activity, transaction/filing/as-of dates and survivorship limits. Delayed 13F holdings are not daily buying; no filing is not proof of no trade. Private REDL mechanics stay private.
- Saturday after completed Friday US trading: preserve the **full sourced Bull Team / Bear Team debate** for UBER in owner-facing output, with quantified evidence, challenges and falsifiers; do not choose a winner. Read reference §5 for the full metric/event scope. Finish with the **Manager Decision Packet**, unresolved questions, changes and next evidence. Catch up a missed week in the next daily slot; use a week key to avoid duplicates. Other days: material changes only. Public-safe summary separately; never publish the private debate or shorten it to fit Telegram.
- **Sunday:** verify a sourced coming Monday–Friday global economic-event outlook (policy, industry, AI, cyber, energy, transport/logistics, space/security when material), dates and time zones. Keep the five-day layout and explicit unverified days.

## Output and release

Keep the website layout, extensive full-issue explanations/tables, five market statuses, all desks, source register, archive, corrections and notices. Simplify repeated research/instructions, not output quality or required debate. Keep the Telegram formatter's exact headings/spacing/escaping: THE BIG PICTURE → WORLD WATCH → optional Sunday events/week ahead → MARKET SNAPSHOT → full issue link → notice. `scripts/telegram-message.mjs` enforces field/4,096-character limits; link the full issue instead of truncating it. See reference §7 for limits.

Prepare one coherent public commit against the current remote SHA. Do not change history or delivery revision for maintenance. Run `node --test`, sender `--dry-run`, context report, build, link check, editorial check, `git diff --check` and history check against immutable base. Review facts/privacy separately: tests are not certification. Check expected remote head; reconcile concurrent changes, never force-push.

Main push: validate/build once → deploy Pages → verify deployed issue/revision marker → send only changed issue/revision. Verify workflow and actual receipt; missing configuration is failure, acceptance UNKNOWN requires channel reconciliation before retry. Manual recovery can duplicate sends. Read reference §8 for recovery. No extra retry timer.

Compact `docs/DEDL_STATE.md` only when operational facts change, with dates, supporting paths, unresolved gaps and next action. Reuse existing source registers rather than copying full articles. Git preserves prior handoffs; corrections stay append-only. Keep private owner output outside this repo. A compact GitHub handoff reduces context reload; it does not erase ChatGPT account memory.
